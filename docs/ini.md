# NTRIP 생존 감시: 다중 캐스터 확장 + config.ini 도입 계획

> 상태: **계획 확정 단계 (코드 미수정)**
> 최종 수정: 2026-11-25
> 대상 코드: `V2/` (liveness_main.py, liveness_mailer.py, liveness_excel_writer.py, ntrip/ 패키지)
> 관련 문서: [sourcetable.md](sourcetable.md), [ntrip.md](ntrip.md)

---

## 0. 배경

- 현재는 **gnssdata 캐스터(www.gnssdata.or.kr:2101) 하나만** 감시한다.
- 계정(`NTRIP_USER` / `NTRIP_PASS`)만 환경변수로 받고, 나머지 설정은 모두 `liveness_main.py`의 `LIVENESS_CONFIG` dict에 하드코딩되어 있다.
- 요구사항:
  1. **매시간 지정된 메일 주소로 요약 메일을 발송한다** (대표 요구사항).
  2. 감시 대상을 **서울시**와 **국립해양측위정보원** 캐스터까지 확장한다.
  3. 계정 정보를 **ini 파일**로 관리한다.
- 운영 환경: 회사 우분투 24.04 서버, Python 3.12, `python3-openpyxl` 3.1.2(apt 설치), cron으로 매시간 실행, 메일은 **네이버웍스** SMTP.

## 1. 설계 원칙: ini는 단순하게

> sftpclient를 만들면서 얻은 교훈: 설정 파일에 항목이 많을수록 운영이 어렵다.

- **ini에는 환경마다 달라지는 값만 둔다.** 계정, 비밀번호, 수신자, 캐스터 주소가 여기에 해당한다.
- **나머지는 코드 기본값으로 고정한다.** 대신 사용자가 알아야 하는 정보이므로 **ini 파일 안에 주석으로 명시한다.**
- 기본값을 바꿔야 하는 특수한 상황(민원 진단 등)은 CLI 옵션으로 처리한다.

### 검토 과정 요약

| 안 | 내용 | 결론 |
|---|---|---|
| 1번 | 계정만 ini로 옮기고 캐스터 정보는 코드에 둔다 | 캐스터 추가 시 코드 수정이 필요해서 탈락 |
| 2번 | 캐스터별 설정 전체(protocol, max_workers, 파일 경로 등)를 ini로 옮긴다 | ini가 너무 복잡해져서 탈락 |
| **최종** | **2번 구조에서 항목을 최소화한다.** 캐스터 주소와 계정만 ini에 두고, 나머지는 코드 기본값 | **채택** |

## 2. 최종 config.ini 템플릿

아래 내용이 그대로 `config.example.ini`가 된다. 실제 값은 `config.ini`에 넣는다.

```ini
; ============================================================
;  NTRIP 마운트포인트 생존 감시 설정 파일
; ============================================================
;
;  [이 파일에서 설정하는 것]
;    - 메일 발신 계정과 수신 주소
;    - 감시할 캐스터의 주소와 계정
;
;  [코드에 고정된 기본값]  ※ 바꾸려면 코드 수정 또는 CLI 옵션
;    메일 서버        : smtp.worksmobile.com (네이버웍스)
;    메일 포트/암호화 : 587 / STARTTLS
;    엑셀 첨부        : 항상 첨부
;                       이번 결과 저장 실패 시 해당 파일은 첨부하지 않고 실패 사실을 알린다.
;    요청 방식        : auto
;                       시작 시 캐스터에 NTRIP 2.0으로 1회 요청해 본다.
;                       HTTP로 답하면 2.0, ICY 또는 501이면 1.0으로 고정한다.
;                       탐지 실패 시 2.0을 사용한다. 정상 수신을 보장하는 탐지는 아니다.
;                       민원 진단 시: --protocol all
;    마운트 목록      : Sourcetable 자동 조회 (auto)
;                       조회에 실패하면 mounts/<캐스터명>.txt를 보조로 사용한다.
;                       정상적으로 완전히 수신한 목록만 보조 파일에 저장한다.
;    동시 접속 수     : 15
;    접속/수신 대기   : 10초 / 10초
;    판정 기준        : 10초 안에 100바이트 이상 수신하면 양호
;    관측소 정보      : metadata/<캐스터명>.json (캐스터마다 별도 파일)
;                       식별자는 영문 관측소 코드다. 한글명·소속기관은 사람이 나중에 채운다.
;                       식별 가능한 미등록 코드는 그 캐스터 파일에 빈 항목으로 자동 추가한다.
;                       한글명이 비어 있어도 경고하지 않는다. 엑셀·메일에는 마운트명을 쓴다.
;    엑셀 저장 위치   : output/생존현황_<캐스터명>.xlsx
;    로그             : liveness.log
;
;  [보안]
;    - 서버에서는 chmod 600 config.ini
;
; ============================================================

[smtp]
; 메일을 보내는 네이버웍스 계정 주소 (support 계정이 자기 자신에게 보낸다)
user = support@valuespace.info
; 네이버웍스 로그인 비밀번호가 아니라 "외부 앱 비밀번호"
password = ********
; 요약 메일을 받을 주소. 여러 명이면 쉼표로 구분
mail_to = support@valuespace.info

; ------------------------------------------------------------
;  캐스터 설정
;  - 섹션명 [caster:이름]의 "이름"이 메일, 로그, 엑셀 파일명에 쓰인다.
;  - 캐스터를 잠시 끄려면 섹션 전체를 ; 로 주석 처리한다.
; ------------------------------------------------------------

[caster:gnssdata]
host = www.gnssdata.or.kr
port = 2101
user = ********
password = ********

; 접속 정보를 확보한 뒤 아래 섹션의 주석을 해제한다.
;[caster:seoul]
;host = (서울시 캐스터 주소)
;port = 2101
;user = ********
;password = ********

;[caster:nmpnt]
;host = (국립해양측위정보원 캐스터 주소)
;port = 2101
;user = ********
;password = ********
```

## 3. 코드 기본값 정리

| 항목 | 기본값 | 바꾸는 방법 | 비고 |
|---|---|---|---|
| SMTP 서버 | `smtp.worksmobile.com` | 코드 | 네이버웍스 |
| SMTP 포트 / 암호화 | 587 / STARTTLS | 코드 | 465(SSL)는 쓰지 않음 |
| 엑셀 첨부 | 항상 첨부 | 코드 | 이번 결과 저장에 성공한 파일을 첨부한다. 용량 증가에 대한 대비는 7절 참고 |
| 요청 방식 (protocol) | `auto` | CLI `--protocol v1/v2/client/both/all` | 이미 구현된 `detect_caster_version` 사용 |
| 마운트 목록 출처 | `auto` (Sourcetable 우선) | CLI `--source file/caster` | 원래 설계로 되돌림 ([sourcetable.md](sourcetable.md)) |
| 보조 마운트 목록 | `mounts/<캐스터명>.txt` | 코드 | Sourcetable 조회 실패 시에만 사용. 조회 성공 시 이 파일이 캐시로 갱신된다. 지금 루트의 `mounts.txt`는 구현 시 `mounts/gnssdata.txt`로 옮긴다 |
| 동시 접속 수 | 15 | 코드 | gnssdata에서 503이 나면 낮추는 것을 검토 |
| 접속 / 수신 대기 | 10초 / 10초 | 코드 | |
| 판정 기준 | 100바이트 이상 | 코드 | RTCM 프레임 검증은 3차 작업 |
| 관측소 메타데이터 | `metadata/<캐스터명>.json` | 코드 | 캐스터별 파일. 5절 참고 |
| 엑셀 파일 | `output/생존현황_<캐스터명>.xlsx` | 코드 | 캐스터별로 파일 분리 |

### protocol 기본값을 auto로 하는 이유

- v1과 v2는 요청 헤더와 응답 처리 방식이 다르다. 같은 스트림을 정상 수신하면 같은 판정이 나올 수 있지만, 캐스터 구현과 클라이언트의 응답 처리에 따라 결과가 달라질 수 있다.
- 없는 마운트에 Sourcetable을 반환하거나 404로 응답하는 경우, 현재 프로그램은 둘 다 "미등록"으로 판정한다.
- `auto`는 캐스터별 검사 시작 시 **첫 마운트에 v2 요청을 한 번 보내고 응답 형태로 검사 버전을 선택**하므로, ini에 protocol을 적을 필요가 없다.
  - HTTP 501 또는 ICY 응답: v1 선택
  - 그 외 `HTTP/` 응답: v2 선택. **HTTP 401·503 응답도 여기에 포함된다.**
  - 탐지 실패: v2 기본값 사용
- 따라서 `auto`는 정상 데이터 수신까지 검증해 가장 잘 되는 버전을 고르는 기능이 아니다. 선택된 방식의 양호 판정이 다른 요청 방식의 정상 수신까지 보장하지도 않는다.
- 민원 진단 시 `--protocol both/all`로 요청 방식별 결과를 비교한다.
- 자세한 내용은 [ntrip.md](ntrip.md)를 참고한다.

## 4. `[smtp]` 항목 설명

대표 요구사항: **`support@valuespace.info`로 매시간 요약 메일을 보낸다.**

### 확정 구성: support 계정이 자기 자신에게 보낸다

- `valuespace.info` 메일은 **네이버웍스**에서 운영된다 (확인됨).
- 발신 계정과 수신 주소를 모두 `support@valuespace.info`로 한다. 별도 발신 계정을 만들 필요가 없다.
- `support@valuespace.info` 계정에는 담당자가 로그인할 수 있다. 외부 앱 비밀번호도 담당자가 발급한다.

### SMTP 동작 방식

파이썬은 메일을 **작성**할 수는 있지만 받는 사람에게 **직접 배달**하지는 못한다. 중간에 메일 서버(우체국)를 거쳐야 하고, 메일 서버는 스팸 방지를 위해 **자기 회원만** 메일을 보낼 수 있게 한다. 그래서 로그인이 필요하다.

```
파이썬 (liveness_mailer.py: 메일 작성)
   │ ① 로그인: user + password (외부 앱 비밀번호)
   │ ② 전달: "mail_to로 보내주세요"
   ▼
네이버웍스 SMTP 서버 (smtp.worksmobile.com:587, STARTTLS)
   │ ③ 배달
   ▼
support@valuespace.info 메일함
```

- **SMTP**는 ①, ②에서 파이썬이 메일 서버와 대화하는 규칙이다.
- 메일 서버를 거치지 않고 받는 쪽 서버에 직접 보내는 방법도 기술적으로는 있다. 하지만 대부분 스팸으로 분류되거나 차단되어 쓰지 않는다.

### 항목 설명

| 키 | 의미 | 값 |
|---|---|---|
| `user` | **메일을 보내는 계정** (우체국 회원 아이디). 받은 메일의 "보낸 사람"에 표시된다 | `support@valuespace.info` |
| `password` | 그 계정의 **외부 앱 비밀번호.** 네이버웍스 로그인 비밀번호와 다르다. 이 프로그램 같은 외부 프로그램이 SMTP로 로그인할 때 쓰도록 따로 발급받는 비밀번호다 | (발급 후 입력) |
| `mail_to` | **메일을 받는 주소.** 여러 명이면 쉼표로 구분한다 | `support@valuespace.info` |

### 참고

- 받는 사람을 나중에 추가하려면 `mail_to`에 쉼표로 이어 쓰면 된다. 예: `mail_to = support@valuespace.info, 다른주소@valuespace.info`
- `support@valuespace.info` 계정의 로그인 비밀번호를 바꿔도 외부 앱 비밀번호는 그대로일 수 있다. 다만 외부 앱 비밀번호를 삭제하거나 다시 발급하면 ini도 같이 바꿔야 한다.
- 외부 앱 비밀번호 발급 전 확인 사항:
  - 네이버웍스 관리자 설정에서 **IMAP/SMTP(외부 메일 프로그램) 사용이 허용**되어 있어야 한다.
  - 2단계 인증을 쓰는 계정은 외부 앱 비밀번호가 필수다.
  - 정확한 메뉴 위치는 네이버웍스 관리자나 도움말에서 확인한다.
- 발송 실패 시 로그(`liveness.log`)에 `메일 인증 실패` 또는 `메일 발송 실패`가 남는다.

## 5. 관측소 메타데이터 동기화 (반자동, 캐스터별 파일)

영문 관측소 코드와 마운트명이 식별자다. Sourcetable에도 한글 관측소명과 소속기관은 없다. 한글 정보는 사람이 비어 있는 칸을 나중에 채우는 부가 정보이며, 이번 범위에서는 DB 연동이나 자동 번역을 하지 않는다. 한글명이 비어 있어도 검사는 그대로 진행한다.

파일은 **감시 캐스터마다 하나씩** 둔다. 소속기관(국토지리정보원, 한국천문연구원 등)별로 나누지 않는다. 소속기관은 파일 안의 `agency` 값이고, gnssdata 한 파일 안에 여러 소속기관이 함께 있는 것이 정상이다. 파일을 캐스터 단위로 나누는 이유는 코드 충돌이다. gnssdata의 `CHJU`가 국토지리정보원 제주인데, 해양 캐스터가 다른 제주 기준국을 같은 `CHJU`로 올리면 공용 파일에서는 한글명과 기관이 한쪽으로 덮인다.

| 캐스터 섹션 | 파일 | 비고 |
|---|---|---|
| `[caster:gnssdata]` | `metadata/gnssdata.json` | 지금 루트의 `station_metadata.json`(147개)을 구현 시 이 경로로 옮긴다 |
| `[caster:seoul]` | `metadata/seoul.json` | 처음에는 빈 객체 `{}`. 검사 때 코드만 빈 항목으로 쌓인다 |
| `[caster:nmpnt]` | `metadata/nmpnt.json` | 서울과 같다 |

ini에는 경로를 넣지 않는다. 섹션 이름의 캐스터명으로 경로를 정한다.

방식:

1. 그 캐스터 검사에서 관측소 코드를 식별할 수 있고, 그 캐스터 JSON에 없으면 빈 항목을 추가한다. 다른 캐스터 파일은 건드리지 않는다. 사람이 채운 값은 덮어쓰지 않는다.

   ```json
   "GGEO": { "station_name": "", "agency": "" }
   ```

2. 한글명이나 기관이 비어 있으면 엑셀 관측소명 칸은 빈칸이다. 기관이 비어 있으면 그 캐스터 엑셀의 `소속미확인` 시트에 모인다. 마운트명은 그대로 표시한다. **미매칭 경고 메일은 보내지 않는다.**
3. 사람은 필요할 때 그 캐스터 파일의 빈칸만 채운다. 다음 실행부터 그 캐스터 엑셀에 반영된다. 같은 코드가 다른 캐스터에도 있으면 각 파일에 따로 적는다. 같은 관측소면 같은 글을 두 번 적고, 다른 관측소면 각자 맞게 적는다.

**관측소 코드 식별:** 현재는 하이픈 앞을 코드로 사용하지만, `YNJU_RTCM30`처럼 밑줄을 쓰는 이름도 있다. 확인된 명명 규칙으로 식별 가능한 코드만 연결하고, 불명확한 이름은 임의로 잘라 JSON에 추가하지 않는다. 이런 항목도 원래 마운트명으로 검사·기록하며 한글명은 비워 둔다. 서버에 요청하는 마운트명 자체는 변경하지 않는다.

현재 gnssdata 파일 상태: 관측소 147개, 소속기관 5곳 등록. GGEO, HSDO, JINJ, YECH, SGWI, GOJE, JJHG 7개가 미등록이다. 이 7개도 한글을 지금 채울 필요는 없다. 구현 때 빈 항목으로 추가되면 된다.

| ③ | **캐스터 반복 실행.** 캐스터마다 checker와 writer를 생성한다. 엑셀은 캐스터별 파일로 저장한다 | `liveness_main.py` |
| ④ | **캐스터 단위 장애 격리.** 한 캐스터가 실패해도 나머지는 계속 검사하고, 실패 사실을 메일에 포함한다 | `liveness_main.py` |

## 7. 주의사항

1. **비밀번호 보안**
   - 서버에서는 `chmod 600 config.ini`로 cron 실행 계정만 읽을 수 있게 한다.
   - 현재 root로 작업 중이다. 가능하면 일반 계정의 crontab에 등록한다.
2. **configparser 보간 문제**: 비밀번호에 `%`가 있으면 기본 `ConfigParser`에서 오류가 난다. `ConfigParser(interpolation=None)`을 쓴다.
3. **마운트명 충돌**: 결과 dict의 키가 마운트명이다. 캐스터별로 검사와 저장을 분리하면 충돌하지 않는다.
4. **엑셀 용량과 속도**
   - 현재 누적 엑셀은 약 300KB다. 지금까지는 하루 1~2회 실행한 이력이라 이 정도다. 매시간 실행하면 훨씬 빨리 커지므로 메일 첨부 한도를 넘기 전에 대비가 필요하다. 예: 월별 파일 분리.
   - 저장에 약 70~75초가 걸린다. 매번 과거 이력 전체를 재동기화하기 때문이다.
   - 약 1.9년 뒤 엑셀 최대 열 수(16,384)에 도달한다.
   - 이번 작업 범위는 아니며, 후속 과제로 둔다.
5. **동시접속 제한**: gnssdata는 병렬 15에서 매번 503이 12건씩 발생한다. Sourcetable로 전환하면 감시 대상이 508개에서 562개로 늘어나므로 503이 더 늘 수 있다.
6. **메일이 안 오는 상황 방지**
   - 검사 결과는 엑셀 저장 성공 여부와 별도로 보존한다. 저장 실패 시에도 결과와 저장 실패 사실을 메일에 포함한다.
   - 이번 결과 저장에 성공한 엑셀만 첨부한다. 저장 실패 시 남아 있는 과거 파일을 이번 결과처럼 첨부하지 않는다. 다른 캐스터의 저장 성공 파일은 정상 첨부한다.
   - 검사 결과가 0건이거나 캐스터 검사가 실패해도 조용히 정상 종료하지 않고, 검사 불가 사실을 메일에 표시한다.
   - 메일 발송 실패는 로그에 기록하고 0이 아닌 종료 코드로 반환한다.
7. **타임존**: 서버가 Asia/Seoul인지 `timedatectl`로 확인한다.
8. **Sourcetable 캐시 보호**: 일부 STR 줄을 읽었다는 이유만으로 성공 처리하지 않는다. 응답의 완전한 수신 여부를 확인한 후 임시 파일에 저장하고 교체한다.
   - 완전 수신 기준: 응답 끝에 `ENDSOURCETABLE` 줄이 있어야 한다. `Content-Length` 헤더가 있으면 받은 본문 크기도 일치해야 한다. gnssdata 응답은 두 가지를 모두 갖추고 있음을 확인했다 (2026-11-25).
   - 현재 `ntrip/sourcetable.py`는 수신 중 타임아웃이 나도 그때까지 받은 내용을 성공으로 반환하므로 이 기준을 추가해야 한다.
   - 조회·파싱·저장 실패 시 기존 정상 캐시를 유지한다. 보조 목록 사용 시 메일에 그 사실을 표시하며, 캐시도 없으면 해당 캐스터의 검사 불가로 처리한다.

## 9. cron 등록 예시 (우분투 24.04)

```
0 * * * * cd /경로/V2 && /usr/bin/flock -n /tmp/liveness.lock /usr/bin/python3 liveness_main.py --mail >> cron.log 2>&1
```

- `flock`은 이전 실행이 끝나지 않았을 때 중복 실행을 막는다.
- ini 도입 후에는 crontab에 환경변수를 적을 필요가 없다.
