와이어샤크 준비되셨군요. 클래스 설명부터 드리겠습니다.

먼저 짚을 게 하나 있습니다 — **8개 모듈 중 클래스가 있는 건 5개뿐**입니다. `protocol.py`와 `policy.py`는 의도적으로 함수만 두었습니다. 상태를 들 이유가 없는 순수 변환 로직이라 클래스로 감싸면 불필요한 인스턴스화만 생깁니다.

호출 흐름 순서대로 설명드리겠습니다.

## `models.py` — 데이터 구조

**`NtripVersion(str, Enum)`** — 요청 변형 3종(`V1`/`V2`/`CLIENT`). `str`을 상속한 이유는 CLI에서 넘어온 문자열로 바로 `NtripVersion("v2")` 생성이 되고, 로그 포맷팅에서 `.value` 없이도 문자열처럼 쓰이기 때문입니다.

**`ProtocolMode(str, Enum)`** — 검사 전략 6종. `NtripVersion`과 분리한 이유는 축이 다르기 때문입니다. `AUTO`/`BOTH`/`ALL`은 "버전"이 아니라 "버전을 어떻게 고를 것인가"입니다.

**`COMPARISON_VERSIONS`** — `{BOTH: (V1,V2), ALL: (V1,V2,CLIENT)}`. 비교 모드에서 시도할 변형 목록입니다. `checker`가 이 dict에 키가 있는지로 단일/비교 모드를 분기하므로, **새 비교 모드를 추가할 때 `checker`를 안 건드려도 됩니다.**

**`ProbeResult`** — 관측 결과 3필드(`bytes_received`, `recv_count`, `duration_seconds`).

**`VersionAttempt`** — 변형 1개로 1회 시도한 결과. `both`/`all` 모드에서 변형별 결과를 개별 보존하려고 만들었습니다.

**`MountResult`** — 최종 결과. `status`는 반드시 4개 값 중 하나여야 하고(엑셀·메일이 문자열 비교로 집계), 나머지는 진단용입니다. `version_attempts: List[VersionAttempt]`가 비교 모드의 원본 데이터입니다.

## `protocol.py` — 요청 생성 / 응답 헤더 해석

**`RequestProfile`** (frozen dataclass) — `http_version`, `send_version_header`, `user_agent` 3개. `PROFILES` dict가 `NtripVersion → RequestProfile` 매핑을 갖습니다. **새 변형이 생기면 여기 한 줄만 추가하면 됩니다.** exe 분석으로 `CLIENT` 변형을 추가할 때 실제로 이 dict에 한 줄만 넣었습니다.

주요 함수:
- `build_request()` — 프로필을 보고 요청 바이트를 조립. 소켓을 모릅니다.
- `parse_status_code()` — `\b(\d{3})\b` 정규식. `HTTP/1.1`의 `1.1`은 3자리 연속 숫자가 아니라 안 걸립니다.
- `parse_headers(head) -> (status_line, dict)` — 헤더명을 소문자로 정규화. `iso-8859-1`로 디코딩하는 이유는 바이트가 1:1로 매핑돼 **어떤 바이트가 와도 예외가 안 나기** 때문입니다. `utf-8`은 깨진 헤더에서 터집니다.
- `is_icy_response()`, `is_chunked()`, `detected_version()` — 응답 형태 판별.

## `chunked.py` — `ChunkedDecoder`

상태 기계입니다. `_STATE_SIZE`(크기 줄 읽는 중) → `_STATE_DATA`(본문) → `_STATE_CRLF`(본문 뒤 CRLF 건너뛰기) → 다시 `SIZE`, `0\r\n`이면 `_STATE_DONE`.

`feed(data) -> bytes`가 유일한 공개 메서드입니다. 소켓에서 받은 바이트를 넣으면 **순수 payload만** 나옵니다. 반환이 빈 bytes일 수 있는데 이건 오류가 아니라 "청크 경계에 걸려 아직 완성된 payload가 없음"입니다. 호출부가 이걸 종료로 오해하면 안 됩니다.

`_MAX_SIZE_LINE = 64` — 크기 줄이 64바이트를 넘으면 chunked가 아니라고 보고 `malformed` 표시 후 중단합니다. `Transfer-Encoding` 헤더는 있는데 실제로는 raw로 보내는 캐스터 방어용입니다.

## `connection.py` — 소켓 계층

**`HeaderIncomplete(Exception)`** — 헤더 종료 전에 연결이 끊긴 경우. `socket.timeout`과 구분해야 재시도 판단이 정확해집니다.

**`recv_header(sock, deadline) -> (head, body_rest)`** — 이게 1차 수정의 핵심입니다. `\r\n\r\n`이 나올 때까지 **누적해서** 읽습니다. 첫 `recv` 1회만 보면 헤더가 쪼개졌을 때 남은 헤더를 데이터로 오인합니다(검증에서 구버전이 417B를 데이터로 셌던 그 버그).

`MAX_HEADER_BYTES = 8192` 안전장치가 중요합니다. `ICY 200 OK\r\n` 뒤에 빈 줄 없이 바로 스트림을 쏘는 캐스터가 있는데, 그러면 `\r\n\r\n`을 찾다가 RTCM 바이너리를 무한정 삼킵니다. 한도를 넘으면 첫 줄만 헤더로 자르고 나머지를 body로 넘깁니다.

**`BodyReader`** — `read(timeout) -> Optional[bytes]`. 반환값 3종 구분이 계약입니다:
- `bytes` (비어있지 않음) — payload
- `b""` — 아직 payload 없음 (청크 경계). **계속 읽어야 함**
- `None` — timeout 또는 스트림 종료. **중단**

chunked면 내부에 `ChunkedDecoder`를 두고, 아니면 raw를 그대로 통과시킵니다. **상위 계층은 chunked 여부를 몰라도 됩니다.**

## `probe.py` — `StreamProbe`

판정 기준(`window_seconds`, `min_bytes`, `min_recv_count`)을 들고 있습니다.

`measure(reader) -> ProbeResult` — 관측 창 동안 payload를 집계합니다. `satisfied()`를 만족하면 창이 끝나기 전에 **즉시 종료**합니다. 1Hz RTCM이면 1~2초에 확정되므로 정상 마운트 검사 시간이 안 늘어납니다.

`satisfied(total, count)`를 별도 메서드로 뺀 이유는 `checker`가 최종 판정 때 같은 기준을 재사용하기 때문입니다. 기준이 두 곳에 중복되면 어긋납니다.

**3차 작업 확장 지점이 여기입니다.** `measure()`의 누적 지점에 `FrameValidator`를 주입하면 RTCM3 프레임(0xD3) 검출과 CRC24Q 검증이 붙고, `policy`나 `checker`는 안 건드려도 됩니다.

## `policy.py` — 판정 규칙 (함수만)

소켓도 HTTP도 모릅니다. "무엇을 받았는가"를 "어떤 상태인가"로 바꾸는 규칙만 있습니다.

- `decide_response(code, sourcetable_returned)` — 상태 라인만으로 확정 가능한 판정. `(status, detail, retryable)` 또는 **`None`을 반환하는데, `None`이 "200이니 body를 봐야 안다"는 신호**입니다.
- `decide_stream(probe, satisfied) -> (status, detail)` — 200 이후 관측 결과 판정.
- `combine_versions(statuses)` — 비교 모드에서 여러 변형 결과를 엑셀용 단일 상태로 합칩니다. `COMBINE_PRIORITY = (양호, 무데이터, 오류, 미등록)` 순으로 하나라도 있으면 그걸 씁니다.
- `is_retryable_exception(exc)` — 네트워크 계열 예외만 재시도 대상.
- `HTTP_CODE_MEANING` — 코드→한글 설명. 민원 매뉴얼과 대응됩니다.

## `sourcetable.py` — `SourcetableFetcher`

`VARIANTS` 리스트를 순회하며 마운트 목록을 얻습니다. 캐스터마다 sourcetable 요청 방식이 달라서 v2 → v1 → 가짜 마운트 순으로 시도합니다. `extract_mounts()`는 `STR;마운트명;...` 라인의 두 번째 필드를 모읍니다.

## `checker.py` — `NtripLivenessChecker` (조율)

유일하게 하위 계층을 다 아는 클래스입니다. 메서드 계층이 이렇습니다:

```
check_all(mounts)                      # 병렬 조율 + 로그
  └─ check_mount(mount)                # 모드 분기
       ├─ _check_multi(m, versions)    # both/all
       └─ _attempt_with_retry(m, ver)  # 재시도 루프
            └─ _attempt_once(m, ver)   # 실제 1회 접속
```

**`_attempt_once()`** 가 전체 파이프라인을 엮는 지점입니다: `open_connection` → `protocol.build_request` → `recv_header` → `parse_headers`/`parse_status_code` → `policy.decide_response` → (200이면) `BodyReader` + `probe.measure` → `policy.decide_stream`.

**`_attempt_with_retry()`** 는 `(VersionAttempt, 시도횟수)` 튜플을 반환합니다. `_is_retryable()`이 `True`인 동안만 반복하고, 401/404/무데이터는 즉시 확정합니다.

**`_check_multi()`** 는 변형 목록을 받아 각각 시도하고 `version_attempts`에 전부 보존합니다. `_check_both`가 아니라 `_check_multi`인 이유는 `ALL`(3개)이 추가될 때 함수를 안 고치려고 일반화했기 때문입니다.

**`detect_caster_version()`** — `auto` 모드 전용. v2 요청 1회를 보내 501이면 v1, ICY 응답이면 v1, `HTTP/`면 v2로 확정합니다. 지금은 2.0 지원이 확인됐으니 안 쓰이지만, 다른 캐스터에 붙일 때 필요합니다.

`_log_version_comparison()`이 비교 모드 결과를 뽑는 곳입니다. 변형별 조합을 `Counter`로 세고 불일치 마운트를 나열합니다.

## 의존 방향

```
checker ─┬─ policy ─┐
         ├─ probe ──┼─ models
         ├─ sourcetable ─ protocol ─┘
         └─ connection ─ chunked
```

**하위는 상위를 절대 import하지 않습니다.** `policy`가 `connection`을 모르고, `protocol`이 `checker`를 모릅니다. 그래서 3차에 RTCM 검증을 붙일 때 `probe`만 열면 됩니다.

와이어샤크 쓰실 때 캡처 필터는 `tcp port 2101`, 표시 필터는 `tcp.port == 2101`입니다. 클라이언트로 접속한 뒤 첫 패킷을 잡아서 `Follow TCP Stream` 하시면 요청 헤더 원문이 그대로 보입니다. `Ntrip-Version` 헤더가 실제로 나가는지 그 화면에서 바로 확정됩니다.
